# 工程3 独自タスク「検査姿勢への到達」設計(2026-10-16)

## タスク
- 製造業の外観検査を想定。対象物の真上にカメラ(手先)を真下向きに構え、静止(撮像)して直立に戻る
- 対象位置は3か所: 左・中央・右(関節1 = -0.5 / 0 / +0.5 rad)。根元から水平 12cm、手先の高さ 8cm
- 観測(environment_state)に「対象の方向」と「経過時間」を入れる予定(pekori で効いた経過時間の工夫を引き継ぐ)
- 評価案: 位置ごとの到達誤差、学習に使っていない位置(±0.25 rad)での汎化

## 決めたこと・理由
- カメラ画像は使わない: rosbag に画像トピックがなく、Gazebo のカメラ定義(camera.urdf.xacro)にも画像を出すプラグインが見当たらない。CPU で画像学習は重く期限に合わない
- 検査姿勢は順運動学で算出(`work/scripts/inspect_pose.py`): 関節2〜4 = +0.330 / -1.187 / -1.630(3か所で共通、関節1だけ変える)
  - 1回目は格子探索が遅すぎて止めた(約50万通り×5方向)。関節1は向きを変えるだけなので、関節2〜4は1回解けば共通、と気づいて約25秒に短縮
- デモはテレオペではなくスクリプトで自動生成(`work/scripts/demo_inspect.py`)
  - 理由: テレオペは1押し 0.05 rad。1エピソード約150回押す必要があり、動きもばらつく
  - テレオペと同じトピック・形式・20Hz で送るので、変換以降は講義の流れのまま
  - 対象方向・姿勢に ±0.03 rad、各区間の秒数に ±10% のばらつきを入れる
  - 各エピソードの対象方向は `~/dataset/rosbags/inspect/targets.json` に保存

## 詰まった点
- 「直立に戻りきらない」警告が出た → 実際のアームは戻っていた。指令ループ内で `rclpy.spin_once` を呼ぶ方式だと、
  /joint_states の値が戻る途中のまま更新されなかった。受信を別スレッド(SingleThreadedExecutor)で回して解決
  - 終了時に `terminate called without an active exception` → 受信スレッドを止めずに終了していたため。executor.shutdown() を追加
- 静止2秒の指令でも、実際に止まっていたのは約1秒 → アームが指令に遅れて追従し、到着時点で静止時間を使っていた。
  静止指令を3秒にして、実際の静止 約2秒(関節2が 0.01 rad 以内)を確認

## 収集・変換(2026-10-16)

## Gazebo 再起動後に1周目だけ動かない問題(2026-10-17)
- 現象: 右パネルなしの Gazebo で撮影(v3)→ 1周目(左)だけアームがほぼ動かず(手先誤差 263mm)、2・3周目は成功
  - 最初の約1.2秒、指令が 0.0203, 0.0238 のまま完全に固定。経過時間が変わっているのに出力が変わらない
- 原因: **グリッパの観測**。学習データのグリッパは常に開(-0.5236)で標準偏差がほぼ 0。
  正規化(平均を引いて標準偏差で割る)で、わずかなずれでも極端な値になり、出力が固まる。
  Gazebo を起動し直した直後はグリッパが 0(開の指令がまだ来ていない)。2周目以降は1周目の指令で開いていたので成功した
  - 確認(`work/scripts/probe_gripper.py`、Gazebo 不要): グリッパ -0.5236 なら正常、-0.5(0.02 のずれ)で出力が +0.020, +0.024 に固定 → 撮影時の値と一致
- 対処1: 推論前に直立・グリッパ開へそろえる(0.005 rad 以内)→ **まだ失敗**(許容幅が粗すぎる)
- 対処2: 方策に渡すグリッパの観測を学習時の値(-0.5236)に固定 → 成功(グリッパ 0 から開始して手先誤差 3.4mm)
  - このタスクはグリッパを使わず、学習データでも一定なので、固定しても情報は失われない
  - 考察: 学習中に変化しない観測は正規化で危険。本来は観測から外すか、標準偏差に下限を設けるべき
- 修正後の撮影: `video/deploy_inspect_b8_v4.mp4`(75秒、右パネルなし、**本命**)。手先誤差 3.4 / 7.6 / 5.9mm(平均 5.6mm)
  - v3(`deploy_inspect_b8_v3.mp4`)は1周目失敗の記録として残す(考察の素材になりうる)
